# Tier-2 Broker-Truth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the missing feedback loop: broker truth flows back into the desk (F-1, F-2, F-3), book writes become race-safe (F-26, F-27), and stale prices stop silently pricing new exposure (F-14, F-15, F-16, F-17-alert).

**Architecture:** Two waves. Wave 1: WP-E (gateway: broker-book sweep, `unknown` outcome class, working-order alerts) and WP-G (api: compare-and-set `saveBook`, multi-leg fill fold) — independent. Wave 2 (after both): WP-F (api: terminal-state reconciler joining gateway truth back onto decisions + books, using WP-G's CAS/fold) and WP-H (marketdata stale-tick detection + api option-vs-spot liveness + open-action mark-age gate).

**Tech Stack:** as Tier 1. **Spec:** `context/14-robustness-audit-2026-08-15.md` F-1/2/3/14/15/16/17/26/27 + §Post-implementation review residuals ("booked-but-refused" is what WP-F closes).

## Global Constraints
- Same as the Tier-1 plan (comment style, node:test/vitest conventions, targeted runs while iterating, never weaken an existing test, stay inside your WP's files).
- **Money-path prime directives:** a correction may only REDUCE a booked position or restate its price to the broker's — never increase; the paper rail is never touched by any reconciler; every correction is journalled; everything is idempotent; one bad document never stops a pass; every new interval carries a `.catch` and a single-flight guard.

### Task WP-E: Gateway — broker-book sweep, `unknown` class, working-order alerts (F-1, F-3, F-17-alert)

**Files:**
- Create: `apps/order-gateway/src/broker-sweep.ts`
- Modify: `apps/order-gateway/src/main.ts` (wire sweep; `placeOne` catch), `apps/order-gateway/src/queue.ts` (`markPlaced` outcome + helpers), `apps/order-gateway/src/fills.ts` (OrderShape only if needed), `packages/brokers/src/xts-protocol.ts` (`classifyXtsError`), `packages/brokers/src/xts.ts` (`orderBook()` mapping + place retry policy), `packages/brokers/src/types.ts` (`BrokerOrder.avgPrice`)
- Test: `apps/order-gateway/test/broker-sweep.test.ts` (new), extend `queue.test.ts`, `packages/brokers/test/*` (find the existing xts/protocol test files and extend)

**E1 — the `unknown` error class (F-3).** In `classifyXtsError`, BEFORE the `fatal` fallthrough, classify `/timed out|abort|network|fetch failed|socket hang up|ECONNRESET|ETIMEDOUT|EAI_AGAIN/i` as `'unknown'` (new member of the class union). Semantics, stated in its doc: *the request may have reached the exchange* — retrying could double-place and asserting failure un-books a real position; the broker book is the only thing that can answer. In `XtsAdapter`'s attempt loop: `'unknown'` must NOT retry and must throw (like fatal) but carrying the class — attach it (`(err as {xtsClass?: string}).xtsClass = 'unknown'` or a typed subclass, match the codebase's error idiom). In `main.ts placeOne`'s catch: when the classified class is `'unknown'`, push the trancheId into a NEW `ambiguousTrancheIds` array (NOT `failedTrancheIds`), journal `FAILED, ok:false, errorClass:'unknown', error:'placement outcome UNKNOWN — resolving from the broker book'`. `queue.markPlaced` persists `ambiguousTrancheIds` alongside the others. **No change to `aggregateTranches` is needed:** ambiguous tranches simply aren't in `failed`, so they count as `working` and the order stays PLACED (non-terminal) — exactly right — until the sweep resolves them (E3).

**E2 — `orderBook()` carries the average price.** `packages/brokers/src/types.ts` `BrokerOrder` gains `readonly avgPrice: number | null`; `xts.ts orderBook()` maps `OrderAverageTradedPrice` the same way `ingestOrderUpdate` does. Update the simulator/other implementers of `orderBook()` if any exist (grep).

**E3 — the sweep (F-1 + F-3 resolution + F-17 alert).** New `broker-sweep.ts`, injected deps `{adapter (orderBook), queue, fills (handle, reconcile), journal, ordersCollection (narrow port), notify?, now, log}`, exported `createBrokerSweep(deps, opts)` returning `{run(): Promise<void>}` with an internal single-flight guard. `main.ts` wires it **only when `brokerMode === 'xts'`** on `setInterval(DESK_BROKER_SWEEP_MS ?? 45_000)` with `.catch`. One `run()` does, in order:
1. **Replay broker truth:** `adapter.orderBook()`; for each row, synthesize a `PlacedOrder {brokerOrderId, clientOrderId: row.clientOrderId ?? '', status, filledQty, avgPrice, tradingsymbol}` and `await fills.handle(p)` — `FillWatcher` already resolves truncated ids via `getByBrokerOrderId` and `isMeaningfulUpdate` suppresses repeats, so replay is idempotent by construction (state that in the header; this is the sweep four Tier-0 docstrings promised existed). Rows with `clientOrderId === null` AND no doc by broker id are foreign (manual orders): count them, log once per id per process lifetime, never adopt.
2. **Expire ambiguous tranches:** for docs `state:'PLACED'` with non-empty `ambiguousTrancheIds` and `placedAt < now - (DESK_AMBIGUOUS_TTL_MS ?? 600_000)`: any ambiguous tranche whose broker id / correlation showed up in step 1's book is left alone (its fills resolve it); each one with NO trace is moved `ambiguousTrancheIds → failedTrancheIds` (`$pull`/`$addToSet` via a new `queue.resolveAmbiguous(clientOrderId, trancheId)` method), journalled `errorClass:'fatal', error:'no broker trace after TTL — treating as never placed'`, then `fills.reconcile(base)`.
3. **Working-order alert (F-17, alert-only this tier — auto-cancel/chase is a recorded decision for later):** docs `state:'PLACED'` with `placedAt < now - (DESK_WORKING_ALERT_MS ?? 300_000)` and no `workingAlertedAt`: journal `phase:'STATUS', ok:false, error:'order still WORKING after Ns — check the broker book; a resting exit is not an exit'` + notify + `$set workingAlertedAt` (one alert per order).

**E4 — tests (write first, RED).** broker-sweep.test.ts with fakes: a broker row for a known tranche reaches `fills.handle` with avgPrice; a repeat run replays nothing new (handle called, but assert the fake watcher's dedup — simpler: assert handle called each run and note dedup is FillWatcher's tested property); a foreign row is never handled; an ambiguous tranche with a broker trace is left; one without is failed + reconciled after TTL but not before; working alert fires once. queue.test.ts: `markPlaced` persists `ambiguousTrancheIds`; `resolveAmbiguous` moves the id. Protocol tests: each network-shaped message → `'unknown'`; existing classifications unchanged. Run `node --test 'apps/order-gateway/test/**/*.test.ts' 'packages/brokers/test/**/*.test.ts'` + tsc.

### Task WP-G: API — compare-and-set `saveBook` + multi-leg fill fold (F-26, F-27)

**Files:**
- Modify: `apps/api/src/store.ts` (`saveBook`), `apps/api/src/book.ts` (`applyRoutedFill`), `apps/api/src/service.ts` (callers at :554 and :1198), `apps/api/src/submit.ts` (caller at :1053 + the `saveBook` port type at :288), `apps/api/src/seed.ts` (caller — stays upsert), `apps/api/src/decision-plan.ts` ONLY if a shared re-fold helper naturally lives there
- Test: `apps/api/test/book.test.ts`, `apps/api/test/store-tag.test.ts` or a new `book-cas.test.ts`, plus whichever existing suites exercise the callers (`flatten.test.ts`, `submit.test.ts`, `service.integration.test.ts` run under Mongo)

**G1 — CAS.** `saveBook(key, legs, nowMs, expectedUpdatedAt?)`: when `expectedUpdatedAt` is provided → NO upsert, filter `{tag, mode, updatedAt: expectedUpdatedAt}`, write `updatedAt: Math.max(nowMs, expectedUpdatedAt + 1)` (the strictly-advancing-version rule, copied from `patchStrategy` with its comment), return `'ok' | 'conflict'` off `matchedCount` (undefined matchedCount = matched, same fake-tolerance as patchStrategy). Absent param → existing upsert (seed/create; document why). `StoredBook`/`bookDoc` must expose `updatedAt` (verify; add if missing).

**G2 — multi-leg fold (F-26).** Rewrite `applyRoutedFill`: collect ALL legs whose `instrument.tradingsymbol` matches. If the fill's delta has the SAME sign as the matched legs' net: add to the first same-sign leg (size-weighted re-average, existing rule) or append a new leg when none matches. If OPPOSITE sign (a reducing fill): consume `min(remaining, |leg.qty|)` across the matching opposite-sign legs in array order, removing legs at zero, **never flipping a leg's side**; any remainder past ALL matching legs crosses through zero → append ONE new leg with the fill's side/deskTag/price (the aggregate cross-through-zero behavior survives, per-leg flips do not). The doc comment must tell the `recenter-relief` two-legs-one-contract story from `service.ts:870-874` — that is the case the old first-match fold corrupted. Check `book.test.ts` for tests pinning the OLD single-leg flip behavior: update only those that encode the defect (say which in your report), keep every other expectation byte-identical.

**G3 — conflict-retry at the callers.** Extract one helper (suggest `apps/api/src/book.ts` or `decision-plan.ts`): `refoldOnConflict({store, master, key, routedFills, nextBook, priorBook, nowMs, log})` → re-reads the book doc, re-applies each routed fill onto the FRESH legs via `instrumentForFill(fill, nextBook, priorBook, master.resolveSymbol)` + `applyRoutedFill`, retries the CAS once with the fresh `updatedAt`; a second conflict logs ERROR (`book write lost two races — decision recorded, book NOT updated; reconciler will surface the divergence`) and returns without throwing. Callers: `service.ts:554` (applyDecision — capture `doc.updatedAt` at the `:342` read; the happy path passes it to `saveBook`), `service.ts:1198` (flattenTag fold), `submit.ts:1053` (same; widen the `SubmitDeps.saveBook` port signature at `:288`). `seed.ts` stays upsert.

**G4 — tests (RED first).** book.test.ts: two same-symbol short legs + one netted closing BUY → both legs consumed, none flipped (the F-26 scenario verbatim: t1 SELL 500 + t2 SELL 500, BUY 1000 → empty); partial netted close consumes FIFO leaving the remainder on the later leg; cross-through-zero appends one new leg; same-sign fill still re-averages. CAS: stale `expectedUpdatedAt` → `'conflict'`, nothing written; fresh → ok with advanced version; absent → upsert. Caller-level: a conflicted applyDecision persist re-folds onto the fresh book and lands both writers' legs (Mongo-free fake store with a mutate-between hook, or the integration suite if a hook exists — follow whichever harness `flatten.test.ts` uses).

### Task WP-F (wave 2, AFTER WP-E and WP-G land): API — the terminal-state reconciler (F-2 + the "booked-but-refused" residual)

**Files:**
- Create: `apps/api/src/reconcile-live.ts`, `apps/api/test/reconcile-live.test.ts`
- Modify: `apps/api/src/main.ts` (interval wiring), `apps/api/src/store.ts` (narrow read/write ports it needs, if any are missing)

**Behavioral spec (the prime directives above apply in full):**
1. Every `DESK_RECONCILE_MS` (default 60_000; single-flight; `.catch`), read up to 50 `desk-gateway-orders` docs: `state ∈ {FILLED, PARTIAL, REJECTED, INVALID}`, `deskReconciled: {$ne: true}`, `createdAt > now - (DESK_RECONCILE_LOOKBACK_MS ?? 7d)` — the lookback keeps a first deploy from rewriting months of history in one pass; sorted `createdAt` ascending.
2. For each doc, resolve its decision: `base = clientOrderId`, `decisionId = base.split('#')[0]`, load the `desk-decisions` doc `{decisionId, mode:'live'}`; the fill inside it is matched by `deskTag === doc.desk_tag` (verify against how `rail.ts`/the routing loops set `clientOrderId` and `desk_tag` for BOTH the actions path and the hosted-submit path — read them first; if the hosted path's ids don't fit this shape, reconcile the actions/flatten path only and REPORT the hosted gap honestly rather than guessing).
3. Compute the correction: `bookedQty = fill.qty`; `actualQty = state==='FILLED' ? bookedQty : state==='PARTIAL' ? doc.filledQty : 0` (REJECTED/INVALID → 0; never exceed bookedQty — clamp and journal if the broker reports more). `actualPrice = doc.avgPrice ?? fill.price`.
4. Apply, idempotently: `$set` the decision fill's `qty: actualQty`, `price: actualPrice`, `corrected: {at, fromQty, fromPrice, state}` (skip docs whose fill already carries `corrected`); when `bookedQty - actualQty > 0`, fold a compensating fill `{side: flip(fill.side), qty: bookedQty - actualQty, price: fill.price, deskTag: fill.deskTag}` into the live book through WP-G's CAS + `refoldOnConflict` machinery (a REJECTED open shrinks the phantom leg; a REJECTED close RESTORES the real one — same rule, stated in the comment). Journal every correction to `desk-order-events` (`phase:'STATUS', ok: actualQty === bookedQty, tag, error: 'reconciled: booked Q@P, broker says Q2@P2'`) and fire the existing notifier. Mark the gateway doc `{deskReconciled: true, deskReconciledAt}` LAST (so a crash re-runs the correction — which the `corrected` stamp then makes a no-op).
5. Paper mode: never read, never written. A decision that cannot be found: journal once, mark `deskReconciled` with `reason:'no matching decision'` (do not retry forever).
6. Sanity: `pnlstore.loadFills`/`LiveBook` read the corrected qty on their own next pass — verify by reading how each loads decisions and state the verification in your report (do NOT modify them unless a numeric filter genuinely excludes the corrected doc).

**Tests (RED first), Mongo-free with fake collections in the existing style:** REJECTED open → fill qty 0 + corrected stamp + compensating fold shrinks the book leg + journal + doc marked; PARTIAL 30-of-50 → qty 30, price restated to avgPrice, book shrunk by 20; FILLED with avgPrice → price restated only, no fold; second pass over the same doc → zero writes; paper decision untouched; broker filledQty > booked → clamped + loud journal; missing decision → marked, journalled once.

### Task WP-H (wave 2, parallel with WP-F): staleness — watchdog wired, spot/option liveness split, open-mark age gate (F-14, F-15, F-16)

**H1 — wire the watchdog (F-14).** `KiteFeedPool` gains `health(): { staleTokens: number; oldestAgeMs: number; perSocket: {...} }` aggregating each `KiteFeed.health()` (which exists and has no caller). The 10s health timer in marketdata `main.ts` includes it in the `md.health` payload (`staleTokens`, `oldestAgeMs`) — **gated on market session** (use the repo's own session predicate — grep `isMarketOpen`/`inSession` in `@algomaker/core`; outside 09:15–15:30 IST weekdays publish the numbers but with `session: false` so consumers don't alarm on a closed market). When `session === true`, a socket is connected, and staleTokens exceeds half its tokens for 2 consecutive sweeps → log ERROR (`sockets connected but ticks frozen — resubscribe repair needed`); actual auto-`reconnect()` goes behind `DESK_STALE_RECONNECT=1` (default off — a wrong auto-repair mid-session is worse than a loud log; say so). `routes/system.ts`: marketdata card's detail gains `staleTokens` when non-zero and session is open.

**H2 — spot must not keep options "alive" (F-15).** `QuoteCache`: `#lastAnyTickMs` is bumped ONLY by `update()` (token ticks); `updateSpot` bumps a new `#lastSpotTickMs`; `spot()` gates on the spot clock, `feedAlive()`/`mark()`/`price()`/`quote()` on the token clock. The file-header reasoning gets a paragraph: one spot publisher surviving an option-chain resubscription failure kept every strike's yesterday-price "alive" — the two feeds fail independently and must be judged independently.

**H3 — a hard ceiling prices no NEW exposure (F-16), exits untouched.** `contract.ts` `MarkSource` gains optional `markAge?(instrument): number | null`. `QuoteCache` implements it (age or null). `applyActions`' `open` case (and `resize` only when growing): when `ctx.maxOpenMarkAgeMs` is set and `marks.markAge?.(instrument)` exceeds it → skip with `open: mark is Ns old — refusing to price NEW exposure off a stale quote (DESK_MAX_OPEN_MARK_AGE_MS)`. `close`/`roll`/shrink stay exactly as they are — trapping an exit over a stale mark is the failure mode this repo never chooses (cite the safety.ts governing rule). Thread `maxOpenMarkAgeMs` from env `DESK_MAX_OPEN_MARK_AGE_MS` (default 600_000) through service.ts's ApplyContext construction. `StaticMarks` doesn't implement `markAge` → gate inert in tests that don't opt in.

**Tests (RED first):** pool health aggregates per-socket stale counts; spot-only ticks leave `feedAlive()` false after the dead window while `spot()` stays alive (and the reverse); an open against a 11-minute-old mark skips with the new reason while a close against the same mark books; resize-grow gated, resize-shrink not.
