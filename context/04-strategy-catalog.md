# server/slive — strategy family catalog

156 files, 37,564 LOC, all standalone Node/pm2 processes requiring `../server.js` for `app.models`. Companion data: `sheets/slive-strategies.csv` (one row per file).

> **CORRECTION (verified 2026-07-25).** This document was produced by a survey agent and one claim in it was wrong: that `PaperTrade` calls are "paper only" and that `lion-s25`'s stop-loss never reaches a broker.
>
> `PaperTrade` is **not** paper trading — it is the **order bus**. `server/tools/xtsOrder.js:306-309` opens a MongoDB change stream on the `paper-trade` collection and forwards every order to real XTS broker accounts, translating `order_type: 'StopMarket'` into an XTS `StopLimit` with a computed ±1% limit price (`xtsOrder.js:150-158`). `sparkOrder.js:62-67` does the same for the Spark broker.
>
> So a `trackOrder_slm` stop **is** placed live whenever `xtsOrder`/`sparkOrder` is running. Wherever this document says "paper", read it as **"routed via the order bus"** — whether that becomes a real broker order depends on which consumer daemons are running, not on the strategy code. See `01-system-overview.md` for the full explanation.

## Family narratives

### modern (bn-breakout, atr-band-nifty/-logic, orb-scalp/-logic, orb-fut-core/-logic/-bn/-nifty/-snx) — 10 files, 1,445 LOC

The newest code (committed 2026-07-03 to 07-14), pure paper strategies with a logic/IO split and unit tests in `server/test/`. **bn-breakout**: BankNifty 5-min candle breaks a +-0.09% band off the 09:15-09:20 close -> buys the ATM option; exit at +45pt target, 90-min time-stop, or opposite-line spot stop; one trade per side per day. **atr-band-nifty**: NIFTY band width = Wilder ATR-14/3 of hourly candles, lines frozen at 11:40; entry needs 2 consecutive same-color candles past the line; target is min(+20pt, +30%). **orb-scalp**: one process running BANKNIFTY+NIFTY+SENSEX opening-range breakouts (09:15-09:45) in parallel with isolated per-index state. **orb-fut-core**: a factory function `startOrbFut(config)` — the three `orb-fut-{bn,nifty,snx}.js` files are 7-line config wrappers around it, the cleanest reuse boundary in the whole directory. All trade options/futures via `PaperTrade.trackOrder_v2`, log in read-only via Zerodha for `historyData`+`KiteTicker`, and never call `Account.placeAllAccount`.

### lion-* (30 files) — ATM-crossover short strangle

Every 100pt (or 50pt) crossing of the underlying's rounded ATM strike sells an OTM CE+PE strangle; a closed leg only re-sells after the previous one fully closes. Four execution sub-engines share this idea: **lion** (9 files, pure paper via a MongoDB `OrderUpdate` change-stream state machine), **lion-s25** (6 files, live SELL entry via `Account.placeAllAccount` + stop via `PaperTrade.trackOrder_slm` — see the CORRECTION note below; the stop *is* forwarded live, but on a different broker rail than the entry), **lion-st15/st25** (6 files, live with a trailing stop), **lion-fixedsl** (6 files, live with a fixed % stop). Plus three one-offs: **lion-b25-1** (only file that buys instead of sells), **lion-sp5-1** (single combined-premium stop instead of per-leg), **lion-up-1** (directional: buys near-ATM below the strike, sells OTM above). Suffixes (0020, 1789, m6000, zzJ4351, snx, s25, st15...) are client codes/underlying selectors (FINNIFTY 257801, MIDCPNIFTY 288009, NIFTY 256265, SENSEX 265). 21/30 are in the March-2023 pm2 dump; the rest have 2024-2025 git dates — the whole family reads as actively maintained.

### cheetah-* (14) and hft-*/bn-hft (5) — momentum-fade sellers and volatility averagers

**cheetah** splits into three engines: **trail** (6 files: sell one far-OTM leg opposite momentum, trailing stop, portfolio P&L breaker, LIVE) — `-stp-2117` picks strikes by nearest-to-Rs250 premium instead of a fixed offset, `-bt-2117` mirrors it to the BUY side; **changestream** (3 files: same idea, paper, via the OrderUpdate state machine, `-2117` uniquely re-enables SL re-entry); **b1** (4 files: buys with momentum, martingale qty scaling, capped at 12 lots except `-2117` which is uncapped — a real risk difference). **hft-averaging/hft-multi/hft-nifty/bn-hft** buy a synthetic ATM straddle (put-call parity) and are meant to pyramid on adverse moves, but three of the four set `MAX_AVERAGING_STEPS=1`, which blocks any actual averaging — only `hft-multi.js` (3 strikes, 10 steps) exercises it. **hft-snx-sell.js** is unrelated: no averaging, just alternates LONG/SHORT on stop-outs (real naked-short exposure on the SHORT side). The hft cluster is the newest code outside `modern` (git Sept 2025-Jan 2026).

### bull-*/bulln-* (20) and eagle-* (12) — same trigger, opposite risk models

Both use the ATM-crossover trigger and a shared underlying-suffix scheme (fs=FINNIFTY, ms=MIDCPNIFTY, ns=NIFTY, snx=SENSEX). **bull-\*** always closes and re-sells on a stop: `bull-300`/`bulln-300` sell 6 OTM wing legs (300/400/500pt) and roll the whole basket on breach — `-300i` sells the ITM mirror instead; `bull-m` is a tighter (100/200/300pt), independently-stopped version; `bull-s/-fs/-ms/-ns/-s5/-snx-1` sell a plain ATM straddle with 25% (5% for `s5`) stop and pyramid size UP each cycle; `bull-r` is the inverse, sizing DOWN from 7 lots to 0; `bull-x` runs a continuous 3-strike rolling ladder that never goes flat; `bull-200-1` picks strikes by matching a premium target instead of a point offset. **eagle-\*** never closes at all — no file contains a single BUY order. It pyramids: each time spot nears a sold leg's own premium distance, it sells one MORE leg (or, in `eagle-p-1`, a full new pair), gated only by a Rs10-20 premium floor — pure unhedged short-gamma accumulation with no stop-loss anywhere in the code. All 32 files check out as active by git-date/pm2-dump evidence.

### stgl-* (14) — three sub-engines, all BANKNIFTY

**stgl-mid** (9 files): sell the CE/PE closest to Rs250 premium, 25% SLM stop, mean-reversion re-entry when spot re-crosses the trade-start price. **stgl-p** (2 files): no candle trigger — fires an ATM straddle immediately and chains 2 more entries at progressively lower premium targets (250->200->150) purely off its own stop-outs. **stgl-s** (3 files): one-shot 4-pair wing sell (100/200/300/400pt), no reload; `stgl-sm` is the only paper (not live) member.

### rv-* (9) — two unrelated ideas sharing a prefix

`rv-1.js` is the only file in the directory computing true realized volatility (14-tick log-return stdev) to decide which strangle leg to roll. `rv-2.js`, despite the pairing, actually runs the second, unrelated **rv-40** engine (`rv-40`, `-40n`, `-25n`, `-40e1/e2`, `-s2`, `-40sl`): a mechanical strangle that rolls a leg further OTM on ~40% loss or back toward ATM on ~50-60% profit, capped by `max_sl_count`. `rv-40sl.js` is the only LIVE, portfolio-PNL-breaker-equipped member, via a shared `tools/stoploss.js` utility.

### cp-* (9) — momentum-fade breakout seller

One paper engine: capture a base price, and on a +-N point move sell the option opposite momentum (mean-reversion), with a combined SL/target pair and a day-stop after 2 losses or 1 win. `cp-rs-030` sells the *same*-direction option instead; `cp-b-2040` is the only BUY-side variant; `cp-s-3370` uses absolute point SL/target instead of percentages; `cp-ns-*`/`cp-snx-*` retarget NIFTY/SENSEX. All 9 postdate the pm2 dump (git Aug-Dec 2025).

### p718-* (5) — two unrelated ideas

`p718-1/2/3` gate an OTM strangle on a **Supertrend(14,5)** indicator computed on a synthetic combined CE+PE candle series — the only technical-indicator-driven strategy in the directory. `p718-4/5` instead run dozens of hand-tuned, per-weekday `CronJob` entries (curve-fit-looking SL% per time slot); `p718-4` sells full straddles and self-terminates its own pm2 process via a `Manager.stop()` call at EOD; `p718-5` sells a single leg chosen by option-chain max-pain.

### samlion-* (4), jk-* (3)

**samlion**: one-shot 10-pair wing ladder (0-900pt spacing), the widest static sell in the directory, LIVE, all near-identical. **jk**: same lion-style ATM-crossover strangle; `jk-0020`/`jk-zzJ4351` are paper (change-stream), `jk-m6000` is LIVE with a belt-and-suspenders dual paper+live stop-loss tracker.

### ce-d2*/pe-d2* (6) — the one real spread scanner

Unlike everything else, this scans strike-pair ladders via live order-book depth for a credit spread (buy near, sell 2x further out) above an escalating threshold. `ce-d2p-extra`/`pe-d2p-extra` are structurally different: they use a `Positional.trackOrder` model instead of `PaperTrade` and persist their ladder state to a `StrategyData` record so a pm2 restart resumes rather than resets. All 6 call `otmSelector('SD_2')`, whose weekday switch in `lib/otmSelector.js` has no Thursday branch — a likely latent bug (falls through to `undefined`).

### Single/small families

**biglion-0020**: `lion-0020`'s engine selling 4 layered strangle pairs instead of 1. **dolphin-0020**/**nifty-s-1789**/**nifty-s-sbm95**: LIVE crossover strangle/straddle with a fixed point target instead of a %-stop. **fox-1**: one-shot pair sell/buy that flips side on each of up to 6 trailing-stop hits. **cal-ce**/**cal-pe**: fire-and-forget calendar spread (buy near-week, sell next-week ATM) with no exit logic at all. **snx-orb-1/25/50**: a 3-step LIVE iteration (most recently touched files besides `modern`) breaking the SENSEX **option premium's** own opening range per side, with risk-based position sizing. **fut-100**: perpetual stop-and-reverse futures system that also touches a separate `XtsAccount` model. **target-15**: continuous ATM straddle harvest-and-reload loop with **no stop-loss anywhere in the file**. **candlestrategy(-a006/-test3)**: not strategies at all — WebSocket mirrors of an external site (optionbhai.com)'s trade signals into local `PaperTrade`.

## Canonical modern pattern

The 10 `modern` files share one anatomy (line refs from `bn-breakout.js`, `orb-fut-core.js`): header comment stating the rule + paper-only disclosure (`bn-breakout.js:1-13`) -> requires incl. `cron`, `../server.js`, `zerodha.js`, `KiteTicker.js`, `optionInstruments.js`, `notify.js` (`:15-22`) -> named config constants, or in `orb-fut-core.js:24-29` a `module.exports = function startOrbFut(config)` factory driven by 7-line wrapper files -> state vars incl. `ticksCache` and a single `position` object (`:36-46`) -> `zerodha_init()`, read-only login only (`:49-59`) -> `ticker()` subscribing spot+options in full mode (`:62-74`) -> `runStrategy()`, idempotent daily reset + `optionConfig()` + login + subscribe (`:81-107`) -> cron-triggered phase-setup functions that self-retry via `setTimeout(fn,30000)` on missing data (`:110-132`) -> `checkTicks()` merging into `ticksCache` and firing `checkExits()` synchronously (`:134-142`) -> a 5-min cron `checkBreakout()`/`checkEntry()` wrapped in a concurrency-1 `async.queue` so overlapping `historyData` calls can't race (`:145-166`, `:288-290`) -> `enterPosition()`, which requires a live tick before trading and only flips its "used" flag *after* a successful order (`:178-225`) -> pure `checkExits()` (`:227-242`) -> `closePosition()`, setting `status='CLOSING'` synchronously before any `await` as a re-entrancy guard (`:244-278`) -> `eodExit()` at 15:15 -> a full IST cron block ending in `process.exit()` at 15:30, since pm2 restarts fresh each morning (`:292-304`) -> `bootstrap()`, which runs unconditionally on load and replays any phase functions that should already have fired for a mid-session restart (`:309-320`). Where a `*-logic.js` file exists, it holds only pure, dependency-free functions, each covered by a `server/test/*.test.js` file.

## Duplication assessment

Of 156 files, only the 10 `modern` files (1,445 LOC, 3.8%) are genuinely new architecture. Roughly 120 of the remaining 146 use zero `CronJob` calls at all — a much older, always-on pattern (crossover/breakout detection on every tick, MongoDB `OrderUpdate` change-streams for fill confirmation) — versus 36 files using cron scheduling. Counting distinct *trading ideas* rather than files: ATM-crossover strangle/straddle selling accounts for roughly 90 files across lion (30), bull/bulln (20), eagle (12, a no-stop variant of the same trigger), samlion (4), jk (3), stgl-mid/s (12), biglion/dolphin/nifty-s/fox (5) and shares one core primitive — round the spot to the nearest strike and act on each crossing. A shared helper, `lib/otmSelector.js`, is called by 104 of the 156 files, and for every tag those files actually pass it ('Lion', 'Lion_SNX', 'Cheetah') the function returns 0 regardless of weekday — meaning most "OTM strangle" sellers in the directory are, in practice, selling at-the-money. Genuinely distinct ideas are far fewer: the 4 modern strategies, realized-volatility strike rolling (rv-1), the rv-40 mechanical roller, momentum-fade sellers (cp-*, cheetah trail/changestream), a Supertrend-gated seller (p718-1/2/3), a hand-tuned time-of-day schedule (p718-4/5), a max-pain-directional seller (p718-5), synthetic-straddle averaging (hft-*), a real credit-spread scanner (ce-d2*/pe-d2*), an option-premium ORB (snx-orb-*), a signal mirror (candlestrategy*), and a perpetual stop-and-reverse futures system (fut-100) — on the order of 15-18 distinct ideas total. A rewrite's natural config boundaries, following `orb-fut-core.js`'s factory pattern, are: underlying (token+strike step), OTM/ATM offset, stop/target basis (fixed %, trailing %, fixed points, or premium-target), position-sizing rule (flat/pyramid-up/pyramid-down/martingale), and paper-vs-live execution — five axes that would collapse most of the 146 legacy files into perhaps a dozen parameterized templates.
