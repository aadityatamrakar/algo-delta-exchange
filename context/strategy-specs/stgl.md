# Family `stgl` — canonical parameterized spec

**Scope:** `server/slive/stgl-*.js` — 14 files, 3554 lines, **all BANKNIFTY, all short-option (premium-selling)**.

**Verdict: 3 distinct algorithms, 14 config records.** All three share one identical
~120-line runtime skeleton (login → ticker → chain → strike-pick → sell → stop → maybe re-enter);
they differ only in (a) how strikes are picked, (b) what the stop is measured against, and
(c) whether/when a closed leg is re-sold. A single TypeScript class with three pluggable
policies (`StrikeSelector`, `StopBasis`, `ReentryPolicy`) reproduces every member.

| Idea | Files | One-liner |
|---|---|---|
| **A. `premium-target-strangle-recross`** | 9 | Sell the CE and PE whose live premium is nearest Rs250; per-leg broker stop at 1.25x; re-sell a stopped leg (same strike, all day) whenever spot re-crosses the entry-time spot price. |
| **B. `premium-ladder-chained-straddle`** | 2 | Sell the CE+PE nearest Rs250; combined-premium stop at 1.25x; on stop, buy both back at market and immediately re-enter at Rs200, then Rs150. Max 3 generations, then flat for the day. |
| **C. `atm-offset-wing-ladder`** | 3 | One shot at start: sell N symmetric strangle wings at fixed point offsets from the rounded ATM (100/200/300/400); per-leg stop at 1.25x; **no re-entry ever**. |

## 0. Facts that constrain any rewrite

### 0.1 Execution rail — the CSV is wrong, correct it

`context/sheets/slive-strategies.csv` labels stgl-mid / stgl-p / stgl-s as `live` and only
stgl-sm as `bus-routed`. **All 14 files are bus-routed. None of them ever places a Zerodha order.**

Reason: every file defines `getAccounts()` (which populates `running_accounts` /
`account_quantities`) and **never calls it** — in `stgl-s.js` / `stgl-sm.js` the call is even
explicitly commented out (`// await getAccounts();`). So `running_accounts === []` forever.
`Account.placeAllAccount` (`common/models/account.js:148`) is:

```js
trackOrder(optionInstrument, orderType, strategyTag, multiplier);   // <-- ALWAYS runs
async.map(running_accounts /* [] */, placeOrder, done);             // <-- iterates nothing
```

`Account.trackOrder` (`account.js:112`) inserts a `paper-trade` doc
`{status:'COMPLETE', order_type:'MARKET', tag, tradingsymbol, instrument_token, quantity: lot_size*mult}`
**with no `dataObj`**. `server/tools/xtsOrder.js:306-309` watches that collection and turns
every insert into a **real XTS/Jainam order**. So:

* `Account.placeAllAccount(...)` in this family == "put a MARKET intent on the bus, no correlation id".
* `PaperTrade.trackOrder_v2(...)` == "put a MARKET intent on the bus **with** a correlation id".
* `PaperTrade.trackOrder_slm(...)` == "put a StopMarket intent on the bus with a correlation id";
  xtsOrder rewrites `StopMarket` → `StopLimit` with limit = stop x1.01 (BUY, stop>1000) or
  x1.05 (BUY, stop<=1000), and **`parseInt`s the stop price** (`xtsOrder.js` orderOptions).
* Per-account sizing happens *inside* xtsOrder: `orderQuantity = (quantity/lot_size) * account.strategy[tag]`.
  The strategy always sends `multiplier = 1` (i.e. 1 lot); real size is a DB field per client.
* `productType: 'NRML'` — **positions carry forward, there is no broker intraday auto-squareoff.**

### 0.2 The feedback channel (`OrderUpdate` change stream)

Only `server/tools/smp_order_listener.js:77` and `server/tools/smp_target.js:316` write
`OrderUpdate`. They do it from the XTS websocket `onOrder`, and **only when
`OrderUniqueIdentifier` contains a `|`**:

```js
if (["FILLED","REJECTED"].includes(status) && identifier.includes('|')) {
  OrderUpdate.create({ updateType:'order', strategy: parts[0], params: parts.slice(1),
                       status: orderData.OrderStatus, price: orderData.OrderAverageTradedPrice, ...orderData });
}
```

`orderUniqueIdentifier = [strategyTag, ...dataObj].join('|')`. Consequences:

* Orders placed via `Account.placeAllAccount` (no `dataObj`) produce **no** `OrderUpdate`
  (identifier has no `|`). Entries are therefore fire-and-forget in ideas A, B, and in stgl-s/s2.
* `update.params[0]` is always a **string** (from `split('|')`), even if the strategy stored a number.
* `status` is raw XTS casing: `"Filled"` / `"Rejected"`.

### 0.3 Instrument universe / expiry

```js
const optionConfig = require('../tools/optionInstruments');   // module.exports = config
let optionData = await optionConfig();                        // default underlying 'BANKNIFTY'
```

`config()` **`require()`s a cached file `optionConfig_BANKNIFTY.json`** and only downloads from
Sensibull if the require throws. That file is regenerated by `server/boot/paperstream.js` at
**07:30 IST**. Shape used by stgl:

* `weeklyInstruments` / `nextWeekInstruments`: dict keyed **`` `${strike}${instrument_type}` ``** →
  `{expiry, instrument_token, instrument_type, last_price, lot_size, name, segment, strike, tradingsymbol}`.
  `last_price` in that dict is a 07:30 snapshot and is never used by stgl (live prices come from the ticker).
* Underlying token is hardcoded: `futureToken = 260105` (**BANKNIFTY spot index**, despite the name).
* Expiry roll: `if (moment().day() == 3) currentExpiryOptions = optionData.nextWeekInstruments;`
  — i.e. **on Wednesday only, skip to next week's series**. `stgl-p-2203.js` is the one file that
  omits this.

### 0.4 Daily state reset

`server/boot/paperstream.js:466` (08:45 IST cron) hard-deletes all `paper-trade` docs whose tag is in
`clearStrategies`, which includes **all eight `STGL-Mid-0020-*` / `STGL-Mid-2117-*` tags**
(not `STGL-Mid-3`, not `STGL-25`/`-25-2`/`STGL-M25`, not `STGL_P_*`). This is what makes
stgl-mid's per-process integer `eventId()` counter (restarting at 0 each day) collision-free.
The families whose tags are *not* cleared accumulate docs forever — see risk R7.

### 0.5 Lifecycle / scheduling

* 13 of 14 files call `runStrategy()` at module load — they start when the process starts.
  Only `stgl-p-2203.js` has cron: `new CronJob('50 16 9 * * 1-5', runStrategy)` = **09:16:50 IST start**,
  and `new CronJob('0 22 15 * * 1-5', () => setTimeout(process.exit, 3000))` = **15:22:00 self-kill**.
* Central lifecycle is `server/tools/xtsOrder.js` bottom: `init` 09:13, `startStrategies` (autostart only)
  09:16:30, `stopStrategies` **15:23:50**, `clearOrders` (cancel pending) **15:24:05**, `process.exit` 15:30.
  **`squareOff()` is defined in xtsOrder.js:373 but is NEVER scheduled.** See risk R1.
* `common/models/strategies.json` registers only 4 of the 14: `STGL-Mid-3`→`stgl-mid-3`,
  `STGL-25`→`stgl-s`, `STGL-25-2`→`stgl-s2`, `STGL-M25`→`stgl-sm`, all `autostart:false`,
  no `delay_start` ⇒ manual start from the Manager UI. The 0020-*/2117-*/`STGL_P_*` files are
  started outside the Manager (pm2 direct).
* `STGL_P_2203` is the only stgl tag in `server/tools/saveDailyPNL_smp.js` strategy list.

### 0.6 Shared skeleton (identical in all 14 files)

```
on process start:
  optionData      = await optionConfig()                    # cached BANKNIFTY chain
  futureToken     = 260105
  chain           = (weekday == Wed) ? optionData.nextWeekInstruments
                                    : optionData.weeklyInstruments
  masterAcc       = await Account.findById(app.get('masterId'))
  public_token    = await zerodha_init(masterAcc)           # FULL LOGIN + masterAcc.save()
  ticker.subscribe([futureToken, ...every option token in chain], mode=FULL)

  # NOTE: 'both' timers are unconditional — no tick-availability wait/retry
  after 5000 ms:  <idea-specific arm/entry>

on ticks batch:
  Object.assign(ticksCache, byToken(ticks))
  <idea-specific queue push>          # async.queue(concurrency 1)
```

* Every process opens its **own** KiteTicker (`api_key:'kitefront'`, master account's
  `public_token`) and subscribes the **entire option chain** (~100-180 tokens) in `modeFull`.
* Every process performs a **full Zerodha login and `masterAcc.save()`** at boot. 14 processes
  booting together race on one document. This is precisely the motivation for the target
  single-market-data-service architecture.
* No entry/exit notifications anywhere. `notify()` is only wired to the `OrderUpdate` catch block
  in stgl-mid / stgl-sm. Operationally blind.

## 1. Idea A — `premium-target-strangle-recross`

**Members (9):** `stgl-mid-0020-1..4`, `stgl-mid-2117-1..4`, `stgl-mid-3`
**Tags:** `STGL-Mid-0020-1..4`, `STGL-Mid-2117-1..4`, `STGL-Mid-3`
**Rail:** bus (`Account.placeAllAccount` entry, no correlation id) + bus (`trackOrder_slm` stop, with id)
**Feedback:** `OrderUpdate` change stream on the SLM's `dataObj[0]`

### 1.1 Pseudocode

```
config = { spotToken: 260105, targetPremium: 250, slPercent: 1.25,
           lots: 1, missingTickDistance: 250, rollWeekday: 3 }

state = { tradeStartPrice: null, lastPrice: null,
          ceStrike: null, peStrike: null,
          positionOpen: {CE:false, PE:false},
          armed: false,                       # `checkFlag`
          eventTrigger: {} }                  # slId -> {token, strike, type, action}

# ---------- ENTRY (fires exactly once, T+5s after boot) ----------
takeTrade():
  spot = ticksCache[spotToken]
  if not (spot and spot.last_price):  RETURN        # <-- NO RETRY. dead for the day.
  tradeStartPrice = lastPrice = spot.last_price

  # rank EVERY option in the chain (CE and PE together) by |premium - 250|
  for each opt in chain:
      opt.distance = ticksCache[opt.token]?.last_price
                        ? abs(ticksCache[opt.token].last_price - 250)
                        : missingTickDistance          # 250 (230 in stgl-mid-0020-4)
  sort ascending by distance                            # stable
  ceStrike = strike of first CE in sorted order
  peStrike = strike of first PE in sorted order         # scan stops once both found

  positionOpen = {CE:true, PE:true}                     # set BEFORE the awaits
  sendOrder(ceStrike,'CE'); sendOrder(peStrike,'PE')    # not awaited
  armed = true

# ---------- ONE LEG ----------
sendOrder(strike, type):
  opt      = chain[`${parseInt(strike)}${type}`]
  ltp      = ticksCache[opt.token].last_price           # throws if no tick
  slId     = nextEventId()                              # 0,1,2,... per process
  slTrigger= round(ltp * 1.25 * 10) / 10                # 1 dp; xtsOrder later parseInt()s it
  await Account.placeAllAccount(tag, {}, [], opt, 'SELL')      # -> bus MARKET SELL 1 lot
  optionOrders.push({strike, type, token, entry: ltp, slTrigger, slId, slHit:false})
  eventTrigger[slId] = {token, strike, type, action:'remove_position'}
  PaperTrade.trackOrder_slm(opt, 'BUY', tag, 1, slTrigger, [slId])   # -> bus StopMarket BUY

# ---------- EXIT (broker-side) ----------
on OrderUpdate insert where updateType=='order' and strategy==tag:
  id = update.params[0]
  if eventTrigger[id]?.action == 'remove_position':
      executeSL(id, eventTrigger[id].token, update.price)   # mark the SLM paper-trade doc
                                                           #   status=COMPLETE, order_type=MARKET,
                                                           #   average_price=update.price
      positionOpen[eventTrigger[id].type] = false           # <-- RE-ARMS RE-ENTRY
      eventTrigger[id] = false

# ---------- RE-ENTRY (mean reversion through the entry-time spot) ----------
on every ticks batch (serialised through async.queue concurrency 1), if armed:
  p = ticksCache[spotToken].last_price
  crossedDown = (tradeStartPrice >= p) and (tradeStartPrice <= lastPrice)
  crossedUp   = (tradeStartPrice <= p) and (tradeStartPrice >= lastPrice)
  if crossedDown or crossedUp:
      if not positionOpen.CE: positionOpen.CE = true; sendOrder(ceStrike,'CE')
      if not positionOpen.PE: positionOpen.PE = true; sendOrder(peStrike,'PE')
  lastPrice = p
```

### 1.2 Exit paths (complete list)

| Path | Mechanism | Present? |
|---|---|---|
| Per-leg stop-loss @ 1.25x entry LTP | `trackOrder_slm` → xtsOrder StopLimit at broker | **yes** |
| Profit target | — | **no** |
| Trailing stop | — | **no** |
| Time-based / EOD exit in the strategy | — | **no** (no CronJob) |
| Central squareoff | `xtsOrder.squareOff()` exists but is **not scheduled**; 15:23:50 only *stops the strategy process*, 15:24:05 only *cancels pending orders* | **effectively no** |

⇒ **A stopped-out leg exits; an in-the-money-but-not-stopped leg is carried overnight as NRML.**

### 1.3 Re-entry semantics (the distinguishing feature — preserve exactly)

* `tradeStartPrice` is captured **once**, at the single `takeTrade()`, and **never updated**. The
  re-entry reference is the entry-time spot for the whole day.
* `ceStrike` / `peStrike` are **frozen for the whole day**. Re-entries always re-sell the *same*
  strike, at whatever premium it happens to trade at then (which after a 25% adverse move is by
  definition richer — this is the "mean reversion" edge).
* Each re-entry gets a **fresh `slId` and a fresh stop computed off the new entry LTP** — stops are
  not inherited.
* The two legs are **independent**: CE can be stopped, re-entered, stopped again while PE never moves.
* Re-entry count is **unbounded**.
* Note the boundary condition: on the first tick after entry `lastPrice == tradeStartPrice`, so
  `crossedDown`/`crossedUp` is trivially true — harmless because both legs are open, but it means the
  gate is "price is currently at-or-through the line", not a strict two-tick crossing.
* `armed` (`checkFlag`) is the only guard preventing `checkReEntry()` from running before entry
  (it would otherwise dereference an unset `tradeStartPrice`).

### 1.4 Sizing

Flat, 1 lot per leg per entry (`multiplier = 1`). Real size = `account.strategy['STGL-Mid-…']`
lots, applied per-client inside `xtsOrder`. No pyramiding, no martingale.
**Instance multiplicity is the sizing lever:** `-1/-2/-3/-4` are four *identical* processes for the
same client code; running all four is a 4x position taken at four independently-selected strikes
(each process picks at its own T+5s and keeps its own re-entry state). In the target system this is
`instances: 4`, not four config records.

## 2. Idea B — `premium-ladder-chained-straddle`

**Members (2):** `stgl-p-2117.js`, `stgl-p-2203.js`
**Tags:** `STGL_P_2117`, `STGL_P_2203`
**Rail:** bus for entries *and* exits, both via `Account.placeAllAccount` (no correlation ids at all —
this family never uses `PaperTrade` directly and does not require the `OrderUpdate` stream).

### 2.1 Pseudocode

```
config = { spotToken: 260105, premiumLadder: [250, 200, 150], slPercent: 1.25,
           lots: 1, rollWeekday: 3 /* absent in 2203 */ }

state = { generation: 1, openPairs: [] }

# ---------- ENTRY (T+5s after boot) and RE-ENTRY (from the stop handler) ----------
takeTrade():
  if not ticksCache[spotToken]?.last_price:  RETURN      # <-- NO RETRY
  target = premiumLadder[generation-1]                   # 250 | 200 | 150
  if target is undefined: RETURN                         # 4th call => permanently flat
  generation += 1                                        # <-- INCREMENTED BEFORE ANY AWAIT
                                                         #     (this is the re-entrancy guard)

  for each opt in chain:
      opt.distance = abs(ticksCache[opt.token].last_price - target)   # UNGUARDED, see R4
  sort ascending
  ceStrike = first CE ; peStrike = first PE
  sendOrder(ceStrike, peStrike)

sendOrder(ceStrike, peStrike):
  ceOpt = chain[`${ceStrike}CE`] ; peOpt = chain[`${peStrike}PE`]
  combined = ticksCache[ceOpt.token].last_price + ticksCache[peOpt.token].last_price
  await Account.placeAllAccount(tag, {}, [], ceOpt, 'SELL')
  await Account.placeAllAccount(tag, {}, [], peOpt, 'SELL')
  openPairs.push({ceStrike, peStrike, ceToken, peToken, slTrigger: combined * 1.25})

# ---------- EXIT (locally polled, market buy-back, chained re-entry) ----------
on every ticks batch (async.queue concurrency 1) -> checkSL():
  for (pair, idx) in openPairs:                          # forEach, async cb, NOT awaited
      total = ticksCache[pair.ceToken].last_price + ticksCache[pair.peToken].last_price
      if total > pair.slTrigger:
          delete openPairs[idx]                          # <-- SYNCHRONOUS, BEFORE the awaits.
                                                         #     This is the double-exit guard.
          await placeAllAccount(tag,…, chain[ceStrike+'CE'], 'BUY')
          await placeAllAccount(tag,…, chain[peStrike+'PE'], 'BUY')
          takeTrade()                                    # <-- immediate next generation
```

### 2.2 Exit paths

| Path | Mechanism | Present? |
|---|---|---|
| **Combined-premium** stop: `ce_ltp + pe_ltp > 1.25 x (entry ce+pe)` | local tick poll → two market BUYs on the bus | **yes** |
| Per-leg stop | — | **no** (a leg can double while the pair is flat) |
| Profit target | — | **no** |
| Broker-side resting stop | — | **no** — if the strategy process dies, the position is completely unprotected |
| EOD | `stgl-p-2203` only: `process.exit()` at 15:22:03 — **kills the process, does NOT close positions** | positions carried |
| Central squareoff | not scheduled | **no** |

### 2.3 Sizing / chaining

* Flat 1 lot per leg per generation. At most **one pair open at a time** (generation N+1 is only
  opened from generation N's stop handler).
* Exactly 3 generations per day, at descending premium targets 250 → 200 → 150. After the 3rd stop
  the strategy is flat and inert until restart. `generation` is never reset.
* Because the target *decreases* each generation, each successive straddle is struck **further from
  ATM** (cheaper options = further out), i.e. the ladder de-risks as the day goes against it.
  The reference for the next entry is the *current* spot, not the original — strikes are re-selected.

## 3. Idea C — `atm-offset-wing-ladder`

**Members (3):** `stgl-s.js`, `stgl-s2.js`, `stgl-sm.js`
**Tags:** `STGL-25`, `STGL-25-2`, `STGL-M25`
**Rail:** all bus. `stgl-s`/`s2` = entry via `placeAllAccount` (no id) + stop via `trackOrder_slm`
placed *immediately* off LTP, plus a redundant local poll. `stgl-sm` = entry via
`PaperTrade.trackOrder_v2` (**with** id) + stop placed *only after the fill is confirmed*, off the
**actual fill price**, driven entirely by the `OrderUpdate` change stream.

### 3.1 Pseudocode (`stgl-s` / `stgl-s2` shape)

```
config = { spotToken: 260105, strikeStep: 100, wings: [100,200,300,400],
           rounds: 1, slPercent: 1.25, lots: 1,
           stopBasis: 'entry_ltp', slPlacement: 'immediate' }

# ---------- ARM + ONE-SHOT ENTRY ----------
after 5000 ms:
    lastQuote = ticksCache[spotToken].last_price       # THROWS if no tick yet -> process dies (R5)
    after another 5000 ms:                            # i.e. T+10s
        for each w in wings:  placeTrade(force=true, w)      # 4 calls, NOT awaited

placeTrade(force, offset):
  atm   = round(ticksCache[spotToken].last_price / strikeStep) * strikeStep
  ceOpt = chain[`${atm + offset}CE`]
  peOpt = chain[`${atm - offset}PE`]                   # symmetric wings

  # duplicate guard, keyed by ATM only (NOT by offset) -- see R9
  take = positionsOpen['S'+atm] ? (positionsOpen['S'+atm].CE==0 || positionsOpen['S'+atm].PE==0)
                                : true
  if not take: RETURN false

  ceLtp = ticksCache[ceOpt.token].last_price
  await placeAllAccount(tag,…, ceOpt, 'SELL', 1)
  ceSlTrigger = parseInt(ceLtp * 1.25)                 # integer truncation
  ceSlId      = moment().format('hhmmss')              # 12-HOUR clock, no date  -- see R7
  optionOrders.push({atm, strike, type:'CE', token, slTrigger, slId, slHit:false})
  PaperTrade.trackOrder_slm(ceOpt, 'BUY', tag, 1, ceSlTrigger, [ceSlId])
  ... identical block for PE ...
  positionsOpen['S'+atm] = exists ? {CE:+1, PE:+1} : {CE:1, PE:1}   # written AFTER the awaits
  return true

# ---------- EXIT ----------
# (1) authoritative: the StopLimit resting at the broker (from trackOrder_slm)
# (2) bookkeeping only: local poll, marks the paper-trade doc COMPLETE. Places NO order.
on every ticks batch -> checkSL():
  for (pos, idx) in optionOrders:
      if ticksCache[pos.token].last_price > pos.slTrigger:
          delete optionOrders[idx]
          executeSL(pos.slId, pos.token, ltp)          # mark doc COMPLETE / MARKET / avg=ltp
          positionsOpen['S'+pos.atm][pos.type] -= 1
```

### 3.2 `stgl-sm` delta — the fill-confirmed stop state machine

Entry side (replaces the whole `placeTrade` body):

```
placeTrade(force, offset):
  atm = round(spot/100)*100
  ceOpt = chain[atm+offset+'CE'] ; peOpt = chain[atm-offset+'PE']
  ceId = counter(); eventTrigger[ceId] = {atm, strike, type:'CE', token, sl_trigger: ceLtp*1.25, action:'place_sl'}
  peId = counter(); eventTrigger[peId] = {atm, strike, type:'PE', token, sl_trigger: peLtp*1.25, action:'place_sl'}
  PaperTrade.trackOrder_v2(ceOpt, 'SELL', tag, 1, [ceId])     # correlation id ON the entry
  PaperTrade.trackOrder_v2(peOpt, 'SELL', tag, 1, [peId])
```

Change-stream state machine:

```
on OrderUpdate(updateType=='order', strategy==tag):
  id = update.params[0]
  if eventTrigger[id].action == 'place_sl' and update.status == 'Filled':     # exact casing
        stopPrice = parseFloat((parseFloat(update.price) * 1.25).toFixed(1))  # off the REAL FILL
        newId = counter()
        eventTrigger[newId] = {atm, strike, type, token, action:'remove_position'}
        PaperTrade.trackOrder_slm(chain[strike+type], 'BUY', tag, 1, stopPrice, [newId])
        eventTrigger[id] = false
  elif eventTrigger[id].action == 'remove_position':
        positionsOpen['S'+atm][type] -= 1        # <-- ALWAYS THROWS in stgl-sm (R2)
        executeSL(id, token, update.price)       # <-- therefore never reached
        eventTrigger[id] = false                 # <-- therefore never reached
```

Entry ramp (replaces the 4 unawaited calls):

```
after 5000 ms:
  lastQuote = ticksCache[spotToken].last_price
  await sleep(5000)
  for round in 0..1:                        # rounds = 2
      placeTrade(true, 100); await sleep(1000)
      placeTrade(true, 200); await sleep(1000)
      # placeTrade(true, 300)   <-- commented out
      # placeTrade(true, 400)   <-- commented out
```

⇒ `stgl-sm` = wings `[100,200]`, `rounds = 2` (so 2 lots on each of 2 wings = 8 legs), 1 s spacing.
It has **no** local `checkSL` and does **not** push to any queue from `checkTicks` — it is 100 %
event-driven off the order feedback stream, so it is the only member whose stop is derived from the
**actual fill price** rather than the pre-trade LTP.

### 3.3 Exit paths

| Path | s / s2 | sm |
|---|---|---|
| Per-leg stop @1.25x | broker StopLimit, placed immediately off pre-trade LTP (`parseInt`ed) | broker StopLimit, placed on fill confirmation off the real fill price (1 dp) |
| Local poll | marks the ledger only, places no order | absent |
| Target / trailing / time / EOD | none | none |
| Re-entry after a stop | **none** | **none** |

The `takePositionQ` async.queue is defined in `stgl-s`/`s2` and **nothing ever pushes to it** — the
crossover-reload loop that `placeTrade(forceTrade=false)` was written for was deleted. Hence
"one-shot, no reload".

## 6. MUST-PRESERVE behaviours

**P1 — Order of writes in Idea A's entry.** `position_open = {CE:true, PE:true}` is assigned
*before* `sendOrder` is called, and `sendOrder` is **not awaited**. `eventTrigger[slId]` is
registered **before** `trackOrder_slm` is called. Both orderings matter: the change-stream callback
can fire before the `trackOrder_slm` promise settles, and the re-entry queue drains on the very next
tick. Any rewrite must keep "mark intent, then emit order" — never "emit, then mark".

**P2 — Idea B's `delete openPairs[idx]` is the only double-exit guard.** `checkSL` uses
`Array.forEach` with an `async` callback that is never awaited, so `checkSL()` resolves immediately
and the queue admits the next tick while the two buy-backs are still in flight. The synchronous
`delete` before the first `await` is what stops the same pair being bought back twice. Reproduce
this as an explicit `closing` flag set synchronously.

**P3 — Idea B's `generation += 1` before any await** is the re-entrancy guard that caps the ladder at
3 and prevents two generations opening concurrently. Increment-then-act, not act-then-increment.

**P4 — `async.queue(…, 1)` serialises tick processing.** Every tick *batch* pushes exactly one task;
tasks never run concurrently. Semantics depend on this (`lastPrice` update in A, pair scan in B).
Also note the worker is `fn().then(cb)` with **no `.catch`** — a throw permanently stalls the queue
(see R8); the rewrite must add the catch but must keep the serialisation.

**P5 — `lastPrice` is updated on every evaluation, unconditionally, at the end of `checkReEntry`** —
including the evaluations where nothing is re-entered. Moving it changes the crossing detector.

**P6 — Idea A freezes `ceStrike`/`peStrike` and `tradeStartPrice` for the whole session.** Re-entries
re-sell the *same* strike measured against the *original* spot. This is the strategy's edge, not an
oversight. Idea B does the opposite (re-selects strikes off current spot each generation).

**P7 — Idea A's stop is recomputed from the *new* entry LTP on every re-entry**, and gets a new
correlation id. Stops are never inherited or reused.

**P8 — Idea C's duplicate guard is keyed by ATM only, and is written *after* both awaits.** All four
`placeTrade` calls therefore pass the guard (each runs synchronously up to its first `await` before
any of them writes `positionsOpen`). If you make the wings sequential/awaited without also keying
the guard by offset, wings 200/300/400 will be silently skipped. See R9.

**P9 — `stgl-sm`'s exact-case `update.status == 'Filled'`** and the two-phase
`place_sl` → `remove_position` id handoff (a *new* counter id for the stop, old one nulled). This is
the only member that derives its stop from a real fill price and is the pattern the new class should
standardise on.

**P10 — Wednesday expiry roll** (`moment().day() == 3` → `nextWeekInstruments`). Must become an
explicit `rollWeekday` / "days-to-expiry >= 1" rule, not a hardcoded weekday.

**P11 — `dataObj` is the correlation channel and it is order-sensitive.** `orderUniqueIdentifier =
[tag, ...dataObj].join('|')`; the listener only emits `OrderUpdate` if the identifier contains a
`|`; `params[0]` comes back as a **string**. Any new id scheme must round-trip through
string-join/split and must be unique within the retention window of the `paper-trade` collection.

**P12 — `paper-trade` docs are the P&L ledger, and `executeSL` closing the ledger row is a separate
concern from the position actually closing.** The broker closes the position; `executeSL` closes the
book. Both must happen; today they can diverge (R2, R6).

**P13 — Restart/catch-up: there is none.** Every member rebuilds state from zero, re-enters from
scratch, and has no knowledge of positions already open at the broker. A mid-session restart of any
stgl process **doubles the position** and orphans the previous stops (which keep resting at the
broker, so the orphan is at least protected — except in Idea B, whose stop lives only in process
memory and is lost entirely). The rewrite must add position reconciliation; the legacy behaviour is
not worth preserving, only documenting.

**P14 — 07:30 chain snapshot + 08:45 ledger wipe.** `optionConfig()` `require()`s
`optionConfig_BANKNIFTY.json` (written 07:30 by paperstream) — a cold cache, not a live fetch;
paperstream then destroys all `STGL-Mid-0020-*`/`2117-*` paper-trade rows at 08:45, which is what
makes stgl-mid's from-zero `eventId()` counter safe. Preserve *the invariant* (correlation ids
unique within the ledger's retention window), not the mechanism.

## 7. Bugs, dead code and dangerous behaviour

### Money / correctness

**R1 — No squareoff anywhere, and `productType: 'NRML'`.** No member has an EOD exit. `xtsOrder`'s
15:23:50 cron only *stops the strategy processes*; 15:24:05 only *cancels pending orders*;
`squareOff()` (xtsOrder.js:373) is **never scheduled**. `stgl-p-2203`'s 15:22 `process.exit()` kills
the only thing watching its stop and leaves the straddle naked and unprotected overnight. **Every
un-stopped stgl short is carried to the next session, up to expiry.** Highest-severity finding in
the family.

**R2 — `stgl-sm`: the stop-fill handler always throws, so the ledger never closes.**
`positionsOpen` is declared (`stgl-sm.js:174`) and **read** at line 70 but the code that used to
write it was deleted along with the old `placeTrade` body. So
`positionsOpen['S'+atm][type] -= 1` → `TypeError: Cannot read properties of undefined`, swallowed by
the enclosing `try/catch`, and the two statements after it —
`executeSL(...)` and `eventTrigger[id] = false` — **never run**. Result: the SLM `paper-trade` doc
stays `Pending` forever (P&L and position reports show the short still open) and `eventTrigger`
entries leak. The broker position *does* close. Fix: drop the counter or initialise it; move
`executeSL` first.

**R3 — `stgl-mid-0020-1.js` and `stgl-mid-3.js` pick the wrong strikes.**
```js
async function getOptionPrice(token) { ... }            // line 160
c.distance = Math.abs(getOptionPrice(c.instrument_token) - 250);   // line 179
```
`getOptionPrice` is `async` ⇒ returns a **Promise** ⇒ `Promise - 250` is `NaN` ⇒ `Math.abs(NaN)` is
`NaN` for **every** option ⇒ the comparator returns `NaN` for every pair, which V8 treats as "equal",
so the stable sort leaves the array in chain order. The strategy then sells **the first CE and the
first PE in the Sensibull chain ordering** — not the Rs250 strikes. In practice one deep-ITM leg and
one near-worthless leg. Files 2/3/4 and 2117-1..4 fixed this by inlining the lookup; `-1` and
`stgl-mid-3` never got the fix. `stgl-mid-3` is the one **registered** in `strategies.json`.

**R4 — `stgl-p-*`: unguarded tick lookup in the selector.**
`c.distance = Math.abs(ticksCache[c.instrument_token].last_price - selectByPrice)` throws
`TypeError` for any chain strike that has not ticked yet (routine for far strikes in the first
seconds). `takeTrade` is `async` and called (a) from `setTimeout` and (b) from inside a
non-awaited `forEach` callback — both without a `.catch`. Consequences: (a) the day's first entry
silently never happens; (b) worse — **the buy-back has already executed and the chained re-entry is
lost**, so the strategy goes flat mid-ladder with no signal. `stgl-mid-0020-2..4`/`2117-*` guard
this properly; `stgl-p` never does.

**R5 — `stgl-s`/`stgl-s2`/`stgl-sm`: unguarded `ticksCache[futureToken].last_price` inside a bare
`setTimeout`** (`lastQuote = ...`, line 101/150). It is outside `runStrategy`'s `try/catch`, so if
the spot has not ticked within 5 s of connect it throws synchronously in a timer callback →
uncaught exception → **process death** (pm2 restart, then the same 5 s race again). Note `lastQuote`
is then never read — the crash is caused entirely by dead code.

**R6 — `stgl-mid-3`: string/number `dataObj` mismatch.** It stores
`dataObj: [moment().format('hhmmss')]` (a string, e.g. `"093015"`) but `executeSL` queries
`dataObj: [parseInt(orderId)]` → `93015`. The `findOne` never matches, so the SLM ledger row is
never marked `COMPLETE`. `position_open` still flips, so trading continues — only the books are
wrong. (`stgl-s`/`sm` use `dataObj: [orderId]` without `parseInt`; for `stgl-sm` that's the *other*
mismatch — `counter()` stores a number, `params[0]` returns a string — latent but unreachable
because of R2.)

**R7 — `hhmmss` correlation ids collide across days, and the ledger is never cleared for these
tags.** `stgl-s`/`s2`/`mid-3` build ids from `moment().format('hhmmss')`: **12-hour** clock, **no
date**. `STGL-25`, `STGL-25-2`, `STGL-M25`, `STGL-Mid-3` and `STGL_P_*` are **absent** from
paperstream's 08:45 `clearStrategies` list, so their `paper-trade` docs accumulate indefinitely.
`executeSL`'s `findOne({tag, dataObj:[id], instrument_token})` can therefore match and mutate a
**previous day's** order document. Additionally, CE and PE in the same `placeTrade` almost always
land in the same second and so share an id (disambiguated only by the `instrument_token` clause).

**R8 — No `.catch` on any queue worker.** `async.queue(function (task, cb) { fn().then(cb) }, 1)` in
all three ideas. Concurrency is 1, so a single rejection means `cb` is never called and **tick
processing stops permanently and silently** — the re-entry engine (A) or the stop engine (B, s/s2)
dies while the process stays up and looks healthy. Combined with R4/R5 this is a live hazard.

**R9 — Idea C's duplicate guard is keyed by ATM, not by wing.** `positionsOpen['S'+atm]` is shared by
all four wings. It works today *only* because the four `placeTrade` calls are unawaited and all pass
the guard before any of them writes. It is a latent trap: `stgl-sm`'s ramp is `await`-spaced, so its
second round's `placeTrade(true,100)` would be rejected by the guard — except `stgl-sm` deleted the
guard entirely (and the writes), which is why R2 exists. Any "tidy-up" of Idea C that adds `await`
without re-keying the guard by `(atm, offset)` will silently drop wings.

**R10 — `stgl-mid`: the `remove_position` handler does not check `update.status`.**
`smp_order_listener` emits `OrderUpdate` for `FILLED` **and `REJECTED`**. A *rejected* stop order
therefore looks identical to a *hit* stop: `executeSL` marks the ledger closed and
`position_open[type] = false` **re-arms re-entry**, so on the next spot re-cross the strategy sells
another lot of a leg it never closed — **an unintended, unstopped double short**. `stgl-sm` does
guard this (`update.status == 'Filled'`). This must be fixed in the rewrite.

**R11 — Stop-price precision is thrown away downstream.** Idea A computes
`round(ltp * 1.25 * 10)/10` (1 dp) but `xtsOrder` does `stopPrice: parseInt(orderObj.stopPrice)` and
then derives the protective limit from it. Sub-rupee stop precision is meaningless on this rail;
`stgl-s` already `parseInt`s at source. Pick one and document it.

**R12 — Idea B has no broker-side protection at all.** The pair stop lives only in
`openPairs` in process memory and is enforced by tick polling. Process death, a stalled ticker, or a
stalled queue (R8) = a completely unhedged short straddle. Also `total` becomes `NaN` if either leg
stops ticking, and `NaN > slTrigger` is `false`, so **a data gap silently disables the stop**.

### Operational

**R13 — 14 processes, 14 Zerodha logins, 14 websockets, one master account.** Each file calls
`zerodha_init(masterAcc)` which logs in and does `await account.save()`, then opens its own
`KiteTicker` with `api_key:'kitefront'` and the same token, subscribing the whole chain
(~100-180 tokens) in `modeFull`. Concurrent boots race on the master account document; the ws count
is well past Kite's per-key limit. This is the single strongest argument for the shared tick bus.

**R14 — Tick-availability precondition is a bare 5 s timer with no retry.** Ideas A and B `return`
silently if the spot has not ticked; the strategy is then **inert for the entire session** with no
alert. Idea C crashes instead (R5). The rewrite must wait on a "first tick received for spotToken
and for the candidate strikes" condition with a timeout + `notify`.

**R15 — Stale chain cache.** `optionConfig()` prefers `require('optionConfig_BANKNIFTY.json')` and
only downloads if that throws. If paperstream's 07:30 cron did not run, the process silently trades
**last week's tokens/expiry**.

**R16 — No trade notifications.** `notify()` is only reachable from the `OrderUpdate` catch block in
`stgl-mid`/`stgl-sm`. No entry, exit, stop-hit, or error alerts.

### Dead code to delete, not port

* `otmSelector` required in `stgl-s.js` and `stgl-sm.js`, **never called**. (Family-wide it is the
  function that returns `0` at 87/93 call sites and `undefined` on Thursdays for tag `SD_2` — stgl
  is not exposed to that bug because it never invokes it.)
* `getAccounts()` — defined in all 14, called in none. With it, `running_accounts` stays `[]` and the
  Zerodha rail is dead (§0.1).
* `takePositionQ` (`stgl-s`, `stgl-s2`) — an `async.queue` nothing ever pushes to; the remnant of a
  deleted crossover-reload loop.
* `checkSL` / `checkSLQ` in `stgl-mid-*` — fully commented out (lines 233-249, and the
  `checkSLQ.push` in `checkTicks`). The local poll was deliberately replaced by the broker stop.
* `startTrade` (set, never read), `lastQuote` (set, never read — and the cause of R5),
  `isCrossover` (`stgl-s`: assigned from `forceTrade`, never read), `ATM_Strike` (pushed, never read),
  `channelId = 0` (never used), `CronJob` imported in 13 of 14 files that have no cron,
  `notify` imported but unused in `stgl-p-*`, `positionsOpen` in `stgl-sm` (read-only ⇒ R2).
* `for (i = 0; ...)` in the selector loops of Ideas A and B — **implicit global `i`** (files are
  non-strict, so it works and leaks).
* `positionsOpen = []` / `optionOrders`-with-holes — arrays used as dictionaries, mutated by
  `delete`. Use `Map`.

## 8. Target TypeScript shape

```ts
// One class covers all 14 members.
class StglStrangleSeller implements Strategy<StglConfig> {
  constructor(private cfg: StglConfig, private feed: Feed, private bus: OrderBus,
              private clock: Clock, private log: Logger) {}

  // Feed is injected -> the same class replays history in the backtester.
  // OrderBus abstracts trackOrder_v2 / trackOrder_slm / placeAllAccount so the
  // simulator and XTS are interchangeable rails.
}

// pluggable policies, selected by cfg:
interface StrikeSelector { pick(chain, ticks, ctx): Leg[] }        // nearest-premium | atm-offset
interface StopPolicy     { armFor(leg, fillPx): StopOrder }        // per-leg | pair-combined
                                                                   // pre-trade-ltp | actual-fill
interface ReentryPolicy  { onLegClosed(ctx): Leg[] }               // none | spot-recross | chain-on-stop
```

Non-negotiable additions the legacy code lacks: a real EOD squareoff, `status === 'Filled'` gating on
every order-feedback branch, `.catch` on the tick pipeline, first-tick readiness gating with an
alert, position reconciliation on restart, and per-instance correlation ids that embed the trade date.
